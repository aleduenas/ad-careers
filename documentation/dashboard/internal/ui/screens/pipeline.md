# dashboard/internal/ui/screens/pipeline.go

**Authority:** [dashboard/internal/ui/screens/pipeline.go](../../../../../dashboard/internal/ui/screens/pipeline.go).

Implements the main pipeline screen: navigation, filters, search, sorting and action dispatch.

## Inputs

Receives application models, metrics, theme, repository path and terminal dimensions. Handles keyboard/resize events and refreshed data; caches report summaries.

## Outputs and behavior

Renders the pipeline and emits messages for report/JD viewing, status/discard actions, scanning, drafting and evaluation. Filter tabs are the sole status-totals display. Search matches permanent report number (with or without `#`), company, role, notes and discard reason. Row columns are number, score, company and role, followed immediately by status-colored lifecycle text such as `evaluated 2026-09-20, added 2026-09-18`; Pending shows only `added DATE`, and unavailable historical dates say `unknown`. The lifecycle verb identifies status in flat view. The Evaluated tab stably prioritizes jobs with a generated CV, cover letter or brief within the active score/date/company sort and labels them `[CV]`, `[LETTER]` or `[CV+LETTER]`. Compensation is read from the prefetched report-summary cache and appears without selection when width permits; full report previews remain cursor-loaded. A manual salary edit (`e` → Salary, which writes `jobs.salary_min`/`salary_max`) always overrides the report-cached figure in both the row and the detail preview, rendered as `$X - $Y (edited)` in green via `editedCompensation`/`formatMoney`; the archived report text is left untouched. Discarded reasons also appear when width permits. `c` opens the ordinary status picker on every tab in the order Applied, Rejected, Interview, Offer, Pending, Evaluated; Ghosted is automatic and cannot be selected manually. `x` separately opens the required discard-reason picker; Expired is the first reason, followed by Seniority mismatch, Wrong role, Wrong location, Duplicate and Other. Pending rows show no JD marker (every row has a JD by construction), and `s` cycles score → status date → added → company. Both date sorts are newest first and use the other date to break ties. The status-date sort is labelled after the tab (`evaluated`, `applied`, `interviewed`, `ghosted`, `rejected`, `discarded`, or `status date` on All and Top), and the Pending tab skips it because pending rows have no status date. `e` opens the edit picker for the selected row (URL, role, company inline, dropping non-printable runes such as the NUL some Windows terminals send; JD in the external editor), `v` evaluates on the Pending tab, and `t` opens the task monitor. Refresh preserves selection/search/form state, report summaries and per-job running-task maps, so `RefreshBlocked` covers only pickers and text input; running tasks never block a reload. `SyncTasks` rebuilds the running-task maps from the durable registry on every refresh — the authority for detached work — announcing each task that finished since the previous sync exactly once and never re-announcing tasks that were already finished when the dashboard started. The status row names each running task with the phase and retry its worker last reported. `q` is never blocked: background work is detached and outlives the dashboard. `HasReportSummary` lets the root application load only newly appearing report paths after refresh. The task status row lists every active evaluation and draft in stable job-ID order; active work takes precedence over a recently completed task's message. Actual database mutations and workflow processes are handled by the root application.

## Dependencies and callers

For evaluated and later roles, Enter includes the selected job's ID and cached JD path in `PipelineOpenReportMsg` when a JD is available, so the report viewer can expose the JD shortcut.

Imports Bubble Tea, Lip Gloss, internal model/data/theme and Go display/path helpers. Shares methods with `jdpaste.go` and screen `workflow.go`. Pending/evaluated action rules and duplicate-task guards are tested in the adjacent tests.
